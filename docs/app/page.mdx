# Agent Stack

Agent Stack is a repository of reusable agent workflows, methods, and reference guidance. These docs explain what is available, how the pieces fit together, and where to find the canonical instructions.

## How a task reaches a capability

The repository's root `AGENTS.md` points an agent to the [Skill Issue router](/capabilities/router/skill-issue) at the start of a task or when its intended outcome changes. The router reads the request and available instruction files, then selects an applicable skill. If no native host invocation exists, the root instructions say to read and apply the local `SKILL.md` in context. Once selected, that capability owns its workflow and handoffs.

Skills describe reusable workflows with a concrete outcome. Disciplines describe reusable methods that can support a skill or be selected for a focused task. Guidelines establish domain standards; they inform work but do not route tasks. Playbooks can connect several outcomes into a broader journey.

## Repository map

| Area | What it contains |
| --- | --- |
| `skills/` | Skills and disciplines. `type` in each front matter block determines which it is; instruction files establish availability. |
| `guidelines/` | Reusable standards and references loaded by their consuming workflows. Some nested files are imported source material. |
| `playbooks/` | Larger journeys assembled from capabilities. The current startup file is explicitly an outline. |
| `sources/` | Research records and third-party examples; these are not discovered as capabilities. |
| `evals/` | Objective checkers for selected skills where script-verifiable criteria exist. |
| `agents/` | Reserved for future agent definitions; currently empty. |

The [stack map](https://github.com/josuamittels/agent-stack/blob/main/map.mmd) visualizes resource relationships. Directory names and map nodes alone do not make a planned capability available: check its linked instruction file and lifecycle status.
