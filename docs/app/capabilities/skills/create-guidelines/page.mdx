# Create Guidelines

> **Skill** · **experimental** · **v0.5.0** · updated 2026-10-28

## Purpose

Create or revise reusable guideline documents. Use to define domain standards, conventions, tool usage, or best practices, or to repair a guideline defect found while evaluating a skill.

## Workflow

1. **Define the guide’s purpose and scope.** Identify the reader decisions the guide should support, its consumers, existing standards, and the repository path where it belongs.
2. **Research the subject.** Inspect current guidance and evidence, compare credible approaches, and record the sources and limits that affect the recommendations.
3. **Design practical guidance.** Use [Think Deeper](/capabilities/disciplines/think-deeper) to turn the evidence into clear defaults, alternatives, exceptions, examples, and boundaries.
4. **Write or revise the guide.** Use the [reference template](https://github.com/josuamittels/agent-stack/blob/main/skills/create-guidelines/templates/reference.md) for a new guide; for revisions, edit the existing file and preserve its valid identity and attribution.
5. **Check the result and connect consumers.** Compare the saved guide with the request, evidence, and affected skills. When the user requested a consumer update, hand the relevant guidance and approved scope to [Create Skill](/capabilities/skills/create-skill).

## Inputs

Require an area needing a guideline, or an identifiable existing guideline and the feedback, additional sources, or demonstrated defect to address. Derive the audience, intended coverage, supplied frameworks and standards, relevant versions, target path, and requested consumer skills from the conversation and stack. Ask only about consequential gaps that inspection and reasoning cannot settle.

## Result

Return the guideline path, concise coverage and change summary, requested consumer updates, and a brief internal-verification conclusion stating whether coverage matches the requested breadth and depth, with any material gaps. Link the local research record while retained; explain source contributions in the delivery summary if useful, leaving the guideline body self-contained. For an unapproved revision, return the concrete coordinated proposal and approval question instead of claiming implementation.
